# とっとりトリップ | TOTTORI TRIP

鳥取で「見つけた」「すれ違った」「訪れた」場所を集める、単体静的WebアプリPoC。8-bit風UIとドット絵の猫。インストール・ビルド・APIキー・DB不要。

## 起動・公開

`index.html`, `styles.css`, `app.js` を同じ場所に置き、HTTPSの静的ホストで公開する。ローカル確認だけなら `python3 -m http.server 8000` で提供し `http://localhost:8000` を開く。iOS等の位置情報は原則HTTPSで提供して初めて動作する。

GitHub Pages: 新規リポジトリに3ファイルと `README.md` をpushし、Settings > Pages > Deploy from a branch > main / root を選ぶ。Pages公開はリポジトリのプライバシー設定とアカウント契約に依存する。PoCを公開すると、ページのコード自体は公開される。記録や現在地はpushしない。

## 使い方

- 表示した地点（詳細を開いた地点）を「見つけた」として記録。
- 位置情報を許可して「すれ違い ON」にすると、アプリを開いている間、位置精度80m以内でOpenPOIの施設中心160m以内になったら「すれ違った」を記録。到着や入店の証明ではない。
- 「訪れた」は必ず手動で記録。参考地点は位置が概算のため自動判定しない。
- 旅帖から画像PNGとブラウザ印刷の「PDFとして保存」を利用。バックアップ/復元JSONも提供。
- 風俗ジャンルは18歳以上の本人確認ボタン後のみ表示。検索元の提供範囲・業態の曖昧さから、実店舗網羅は保証しない。

## iPhone地図崩れの追加調査（2026-10-25）

正常動作するマンションポエムとの違いは、鳥取旅帖がLeafletのCSSを外部CDNのSRI付きタグで読み込んでいること、独自の地図ラッパーとUIがあること。CSS取得・適用の失敗が「タイルが1枚だけ見える」状態に関与する可能性を切り分けるため、[Leaflet v1.9.4の公式CSS](https://github.com/Leaflet/Leaflet/blob/v1.9.4/dist/leaflet.css)を `vendor/leaflet.css` に同梱して自サイトから配信する。元のBSD 2-Clause LICENSEは `vendor/LEAFLET-LICENSE.txt` に同梱。

JS読み込みタグはマンションポエムと同じSRIなしの公式unpkg配信にした。別ライブラリへの変更や地図APIの差し替えは行っていない。

**任意の診断**：`https://moyashimisosoup.github.io/tottori-trip/?mapdebug=1` を開くと地図内に `CSS OK/NG`、DOMサイズ/Leaflet内部サイズ、読み込んだタイル/総数、エラー数を表示する。通常のURLでは非表示。CSS NGの場合は自動表示。2026-10-25、ユーザーからiPhoneで地図の欠けが解消したとの実機報告を受領。CSSの自サイト配信とLeaflet JS読込方法の変更を同時に実施したため、単一原因の断定はしない。

## 2026-10-25 地図操作・表示範囲検索

- **検索範囲**：従来の「選択エリア中心から半径6km」ではなく、地図上に表示されている矩形範囲をOpenPOI APIの `bbox=minLng,minLat,maxLng,maxLat` で指定。地図内のマーカー・施設リストも表示範囲内を対象にする（座標未確定の参考地点はリストに残す）。APIの取得上限は200件のため、密集地域で網羅性は保証できない。
- **地図移動後**：地図の移動・ズームだけではOpenPOIを再取得しない。検索済み範囲から外れると「この範囲で再検索」ボタンが現れ、押した時だけ新しい範囲へ問い合わせる。移動後も既取得データの表示範囲絞り込みは即時反映する。
- **ズーム**：市街地でマーカーが重なりにくいよう初期表示・エリア切替時のズームを16に設定。iPhoneではダブルタップ後、2回目の指を置いたまま上へスライドすると拡大・下へスライドすると縮小。通常の1指ドラッグ、2指ピンチは保持。
- **入力欄**：検索フォームの列幅を `minmax(0,1fr)` で制約。入力中のフォーカス枠を内側にし、iOSの自動ズームを避けるため文字サイズを16pxにする。
- **安全な変更範囲**：地理院淡色タイル、Leaflet標準 `L.tileLayer()`、自サイトからのLeaflet CSS配信、端末内の旅帖記録は変更しない。実機での操作感は別途確認する。

## 技術的留意点

- OpenPOI API: `https://api.openpoiapi.com/v1/search`, `center=lng,lat`, `bbox=west,south,east,north`（地図未生成時だけ `radius=6000`）、`limit=200`。認証不要、CORS許可。最大200件のため密集地の網羅は不可。検索は明示操作中心、移動中は300m/1分以上変化時に限定。
- 地図: Leaflet 1.9.4 + [地理院淡色地図（pale）](https://maps.gsi.go.jp/help/use.html)。初期タイルは標準Leafletの `L.tileLayer()` を使用。手動切替時のみOpenStreetMapタイルに変更。地図画像の提供者と施設データのOpenPOI APIは別。大量取得やバックグラウンド取得は行わない。
- 記録: `localStorage`。同期なし、端末間共有なし、ブラウザのデータ消去で消える。保存するのは施設の名称・座標・日時であり、GPSの生の移動履歴は保存しない。ただし近接した施設の履歴から行動が推測され得るためJSONや画像の公開には注意。
- 文化地点の補助データは、県の観光・文化資料から名称と概略の場所を選んだ参考リスト。ピン座標は概略。正確な入口や史跡中心を示すものではない。
- 掲載施設の閉業・座標のずれ・収録漏れ・カテゴリ分類誤差はあり得る。飲食や風俗の表示は営業状況や許認可を保証しない。
- 無断で写真や文章をコピーせず、リンクと必要最低限の要約のみ収録。

## 受入チェック（過剰な自動検査はしない）

1. HTTPSで開いて地図と鳥取市の参考地点が表示される。
2. 実APIを1回検索し、OpenPOIの施設名と距離が表示される。
3. 一つ開いて「見つけた」になり、「訪れた」を押すと旅帖に残る。
4. 位置情報の許可/拒否に応じてステータスが変わる。
5. 旅帖の画像出力・PDF保存とJSONバックアップ/復元ができる。
