# APP-025｜文学検索の結果が地図に見えない問題（2026-10-26）

## 再現条件
iPhone Safariで「高浜虚子」と入力すると一覧に「高浜虚子句碑」が出る一方、地図は以前の表示範囲のままでピンが見えない。検索中に文学から「すべて」へ切り替える場合もある。

## 原因
- 入力イベント `onSearchInput` は一覧だけを更新し、地図の移動は検索フォーム送信後の `focusSearchResults` に依存していた。文字を入れた時点ですでに一覧に結果が出るため、一覧と地図の視点が一致しなかった。
- 「高浜虚子」を含む碑群の説明文も同じ検索語でヒットし、直接一致する句碑と広域碑群が同じ参考座標に重なった。
- Leafletの通常のピンだけでは、検索結果が地図範囲外にあると画面上の見た目で結果を認識できなかった。

## 対応
1. 登録済み地点の検索語入力が収まって約380ms後、名称に一致する施設が1〜5件の場合は、その地点へ地図を自動フォーカス（IME変換中は実行しない）。住所API呼び出しや位置情報取得は不要。
2. 登録施設の名称そのものに一致する結果を、広域碑群の説明文の一致より優先する。「高浜虚子」では句碑1件を優先。登録座標が同一の候補はゼロ幅のfitBoundsではなくsetView。
3. 地図本体レイヤーに目立つ検索強調ピンを表示。通常ピンとの重複は除外し、古い検索語の強調ピンを残さない。
4. 検索確定ボタンにも同じ登録地点優先の動作を適用。検索を消すと検索前の地図位置に戻す。
5. 学習コンテンツや旅帖/GPS関連のデータ、文学76地点・58作品・地理院タイルは不変更。

## 検証
- 実データの「高浜虚子」検索は個別句碑と碑群の説明文が一致する例。直接名前が一致する「高浜虚子句碑」だけが一覧1件に残ることを確認。
- 表示範囲外を模したLeaflet+DOMのイベントテストで「入力→自動地図移動→地図上に強調ピン」「検索ボタン→同じ位置」「消去→元の地図位置」成功。
- 地図位置は参考座標 `35.544,134.220` であり個別句碑の実測地点ではない。
- **未検証**：公開GitHub Pagesの新バージョン配信、iPhone Safariの修正後表示。ライブサイトへの外部取得経路は今回利用不可。

## 次の検収
iPhoneで「高浜虚子」を入力して1秒ほどおき、検索ボタンを押す前に地図が移動して強調ピンが見えるか確認。ボタンを押した場合も同じ位置になるか確認。必要なら地図全体と検索結果が同時に見えるスクリーンショットで絞り込む。
