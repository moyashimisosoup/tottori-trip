# APP-025｜登録住所・地図代表点・近隣すれ違い（2026-10-25）

## 正本とスコープ
- 固定登録スポット106件の住所と元座標を `location-catalog.js` に一覧化（IDは旧データと同一）。
- 構成：既存の `app.js` / `literary-batch-01.js` / `official-landmarks.js` に基づく93件の住所、および公開観光資料で所在地・地域を補足した11件のガイド（ガイド13件のうち2件は元々住所あり）。住所106/106、元の代表座標36/106。
- 住所の粒度：建物の丁目・番地、町域の代表点、文学碑群の地域名が混在する。住所を得たことと施設の個別位置が確定したことを混同しない。
- OpenPOIの動的検索結果は外部検索の応答座標をそのまま使用し、この固定カタログ106件には含めない。

## UI
- 詳細ダイアログから住所の手動入力・保存フォームを撤去。ユーザーは施設名を探して開き「地図で見る」を押すだけ。
- 座標が既存データにある場合はその座標を優先。ない場合は登録住所を地理院地名・住所検索APIへ送信し、結果の代表座標を地図表示に使用。
- 検索は選択エリアにある固定施設の不足座標に対して、画面表示中に自動・逐次実行。問い合わせを1件ずつ行い、重複住所の応答を共通再利用。成功した結果は `tottori-trip-address-cache-v1` に端末保存し、再起動でも使う。
- オフライン・API/CORSエラー・一致しない住所の場合、位置を捏造しない。未取得地点は住所情報だけ表示する。
- `location-catalog.js` の未取得70件は **初期収録時点で座標未解決**。各端末でAPI接続後に取得が進む。全件のAPI通信成功・iPhone Safari実機検収を完了した意味ではない。

## すれ違い
- 目的は「特定の入口に到着」ではなく「近隣を通過した」こと。GPS誤差が140m以内のとき、施設確認済みの点は250m以内、参考住所の代表点は400m以内で判定。
- 名称が同じ多数の文学碑を同じ町代表点に重ねて全件自動判定することは避けるため、「個別の碑位置は未特定」と明示されたグループ・作品の舞台のみの参考地点は自動判定対象外。
- 手動で「すれ違った」「訪れた」を記録する機能はそのまま維持。
- GPS位置履歴をGitHub・外部のAPI・アプリの固定データファイルには保存しない。

## 維持事項
- `tottori-trip-v1` の既存 `localStorage` とJSONバックアップの構造、施設ID、訪問日時は維持。
- Leaflet標準、地理院paleタイル、地図CSS、画像アトラス、テーマ設定は変更しない。
- 住所検索APIは読み取り専用。アプリの住所台帳やGPS記録を地理院APIへ書き込むわけではない。
