# APP-025 検索から地図中心移動・未登録地名検索（2026-10-25）

## 挙動
- 「鳥取駅」で検索したら鳥取駅の代表点（北口周辺ではなく駅そのものの代表座標）`35.49422, 134.226085`へ地図の中心を移し、駅名の検索専用マーカーを表示する。
- 位置がわかる登録済み地点の名称検索は、1件ならズーム15で中心移動、複数なら`fitBounds()`で画面に収める。名前のみの参考地点は推測位置を表示しない。
- 未登録の駅・地名・住所は、**検索ボタンまたはキーボードの検索キーを押した際だけ**、国土地理院の地名・住所検索APIを利用。`geometry.coordinates`の経度・緯度を確認し、鳥取県のおおむねの範囲にある候補のみを採用する。検索語と住所候補が一致しない場合は採用しない。
- 検索に成功した場合は**黄金色の四角マーカー**と検索専用カードを表示。カードをタップすると通常の施設と同じ詳細画面を開き、「みつけた・すれ違い・訪れた」を旅帖へ記録できる。
- 名前検索は一時操作。検索を解除すると地図の検索前の中心・ズームへ戻る。別のエリア選択でも一時マーカーを消す。
- 地理院APIに失敗した場合は、無根拠なピンを立てず、検索不成立・接続不可のメッセージを表示する。検索結果は、同一ページ内で再検索する際だけキャッシュする。

## 根拠・外部API
- 鳥取駅の所在地：[JR西日本公式「鳥取駅」](https://eki.jr-odekake.net/premises?id=0640706)（鳥取市東品治町111番地）
- 鳥取駅の代表緯度経度：[山陰線「鳥取駅」駅位置情報](https://postcode.teraren.com/stations/3895)（35.49422, 134.226085）。駅舎の入口やホーム等の正確な位置ではない。
- 国土地理院「[地名・住所検索](https://msearch.gsi.go.jp/address-search/AddressSearch?q=鳥取駅)」：検索語`q`に対してGeoJSON Feature配列（`properties.title`, `geometry.coordinates=[longitude,latitude]`）を返す公開API。[国土地理院の操作手順](https://web2.gsi.go.jp/chugoku/howtoview.html)。
- 外部Nominatimの共有APIは使わない。現在のGSIサービスの利用条件に従い、ユーザーが検索を確定した時だけ単発呼び出し。大量自動検索・タイプ中の外部検索はしない。
- APIの可用性・CORS・実機Safari通信はまだ検証できていない。動作不能時は無根拠な位置にフォールバックしない。

## 品質・保全
- 検索だけでは旅帖へ保存しない。ユーザーが検索カード・ピンを開くと、通常の施設と同じ `eventFor(...,'seen')` で端末の旅帖へ保存する。確認した地点は次回からも同じIDで参照できる。位置確認済みであれば、出典に関係なく `checkNear()` の候補へ含める。地図タイル`L.tileLayer()`・Leaflet CSS・GPS取得や旅帖JSON形式は変更しない。
- `reqSeq`とは別の`geoReqSeq`で古い応答を無視。検索語を削除した後に遅れて返ってきた住所を表示しない。
- 住所の代表点が実際の入口・建物の位置とは限らないため、「地図検索・未登録」として通常の記録対象から区別する。

## 最小検証
1. 「鳥取駅」の検索で代表点へ`setView`、一時カードが追加され、旅帖件数は変わらない。
2. 地理院APIの模擬Featureから住所位置へ`setView`、県外候補の除外を確認。
3. 「水木しげる」は既存登録済み2地点を`fitBounds`、外部OpenPOIの検索結果も含む。
4. 検索を消すと初期の鳥取市中心へ復帰。既存地図タイルの描画機構は変更しない。

## 判定の統一方針（追加）

### 住所と位置精度は別の情報

国土地理院による地名・住所検索は、入力住所そのものの建物座標ではなく**街区・町丁目・市町村の代表点**が返る場合がある。詳しくは [地理院地図の検索操作と精度上の注意](https://maps.gsi.go.jp/help/pdf/GSIMaps.pdf)。

したがって住所が「ある」こと自体では自動すれ違い許可の根拠としない。**施設代表点を確認できたか**だけを判定条件とする。施設の出典（OpenPOI・鳥取県公式・国土地理院検索・アプリ内データ）では差別化しない。

- 検証済み地点：`verified === true` かつ数値の `lat/lng` がある地点は同じ半径160m、GPS誤差80m以下のすれ違い判定へ。
- 鳥取駅：施設自体の代表地点として座標確認済みのため、検索カードを開いて旅帖に加えれば、通常の自動すれ違い判定に参加する。
- GSI地理院の住所代表点：まず地図に表示し、旅帖では「参考位置」とする。利用者が地図上で施設位置を確認し、「この位置を確認・自動判定に使う」を押すと `verified=true` として保存する。
- 保存された検索地点は `allPlaces()` へ統合。通常のスポットと同じ一覧・詳細画面・旅帖表示を使う。GPS判定候補は `state.results`, `currentGuides()` と**保存済み旅帖地点**から重複IDを除いて組み立て、出典では足切りしない。
- 位置の出所がGSI・公式資料のいずれでも、元の施設IDを維持できる場合は元IDのまま昇格する。IDがない外部検索地点は固有の `search:...` IDにする。
- 公式記録に住所があって座標がない場合、**名称の検索時に限り**、番地・丁目を含む具体的な住所でGSIを再検索する。町名しかないものは、施設と無関係な町中心に自動配置しない。
- 検索だけで「みつけた」を増やさず、詳細画面を開いたときだけ明示的に記録。保存履歴にはGPS移動経路を持たない。

### 限定検証

- 鳥取駅を旅帖に追加してGPSで付近を通ると、1件の`nearAt`を記録し、再度のチェックでは重複記録しない。
- GSIの概略住所を旅帖に追加しても`verified:false`なので自動判定対象外。「この位置を確認」で`verified:true`に切り替えると同じ判定に参加し、再検索しても判定資格を維持。
- 公式観光データの位置確認済み地点も、GSI検索地点も`canAutoDetect`の条件を共通に使用する。
- 実機の外部GSI API通信・施設の個別座標精度・GPSのすれ違い実測は未検収。
