# APP-025｜文学地点は先に地図表示、位置取得は裏側で（2026-10-25）

## ユーザー実機不具合
「高浜虚子句碑」などの施設詳細で「地図で見る」を押しても「住所の代表位置を取得できませんでした」となる。ユーザーの期待は、ボタンを押す**前から**文学地点が地図に存在し、ボタンは単にその地点へ移動すること。

## 修正の要点
1. `withCatalog` は読み込み時点で、登録緯度経度→既存 `referenceArea`→端末で以前取得したGSIキャッシュ→事前整理した文学地域の参考座標の順に利用する。閲覧者による住所入力・座標確認は不要。
2. 新規 `literary-location-seeds-06.js` に23件の**地図専用の初期参考座標**と根拠URLを収録。初回閲覧時から地図へ出す。既存文学碑の参考座標36件も継続利用。文学関連の合計76地点が座標を持つ。
3. 代表点の根拠には、地元の既存登録観光座標、鳥取市公開の尾崎放哉句碑座標、Geoshape（国勢調査地区中心/地名/施設位置）、観光サイトに掲載された参考地区を使用。個別の碑・学校・展示館の入口座標と誤認しないよう `literary-reference` / `referenceLabel` を付ける。
4. 地図上のピン描画対象を、施設カードの最大表示件数（50件など）から分離。対象カテゴリ・画面範囲の全登録地点を描画。
5. 「地図で見る」は最新の登録済み地点IDから表示座標を再取得し、保存済みの古い旅帖地点に座標がなくても移動する。文学地点はAPIの成功を待つ必要がない。まだ代表座標のない一般施設だけ従来の住所API取得を試す。
6. 地図内で砂丘の個別5碑を1つの破線枠「5」ピンにまとめ、別レコード「鳥取砂丘西側 文人歌碑・句碑群」を冊数に数えない。文学書誌58作品の本ピン（砂丘20冊）も維持。
7. 事前参考点は自動GPSすれ違い対象外。GSI住所APIが利用できれば初期参考点をバックグラウンドで補正し、成功分のみ端末キャッシュ。API不通でもピンは消えない。旧の旅帖IDと保存キーは維持。

## 初期参考点の位置精度
- 参考点23件には出所URLを個別保存してある。近隣の既存登録座標を再利用した地点は「周辺の代表位置」であり、場所の入口まで案内するための座標ではない。
- 日野町根雨／日南町神戸上／米子市淀江町福岡／八頭町船岡／粟嶋神社などは地名・地区の公開位置情報を使用。数百m〜数kmのずれは起こり得る。
- 対象施設の正確な座標を後日確認した場合は、IDを維持したまま座標を差し替え、個別の現地位置を案内できるようにする。
- 出所一例：
  - https://geoshape.ex.nii.ac.jp/nrct/resource/32/320000240900.html
  - https://geoshape.ex.nii.ac.jp/ka/resource/31/31401025001.html
  - https://geoshape.ex.nii.ac.jp/ka/resource/31/31202123002.html
